# 角色管理

## 目标

让用户在 Windows 和 Android 上离线创建、编辑、浏览、删除角色，并通过专用 PDF 交换角色卡。角色内容保持开放，不依赖内置职业、种族、法术或专长数据库。

## 用户入口

应用默认进入一级导航“角色”。列表加载应用文档目录中可识别的角色 JSON。

## 列表行为

- 无角色时显示空状态、新建入口和 PDF 导入入口。
- Windows/宽屏使用卡片网格；Android/窄屏使用纵向列表和浮动新建按钮。
- 每张卡展示画像、角色名、ID 前四位、种族/职业、HP、AC 和先攻。
- 空角色名显示“未命名角色”；空种族/职业显示“未配置种族/职业”。
- 点击卡片进入编辑；菜单提供导出 PDF 和删除。
- 页面每次重新进入都会重新从磁盘加载，不缓存上次列表。

本地加载遇到坏文件的目标行为是“提示用户并跳过”。当前服务只跳过并输出到 `stderr`，属于待补齐功能。

## 新建与编辑

新建使用 `Character()` 默认值和新的 UUID v4。编辑分为：

1. 基础信息：角色/玩家姓名、种族、职业与等级、背景、阵营、经验、六项属性。
2. 技能豁免：熟练加值、被动察觉、六项豁免、十八技能、其他熟练与语言。
3. 冒险信息：AC、先攻、速度、最大 HP、最大生命骰、三类以上武器槽、备注、装备、钱币、能力。
4. 人物设定：画像、外貌、个性、理想、纽带、缺陷、盟友、所持物、附加特征、经历、背景故事。
5. 施法信息：施法职业、关键属性、法术 DC、攻击加值、0～9 环法术和准备状态。

表单直接修改内存对象，但不会在每次输入后写盘。“保存并退出”才调用本地保存并更新时间。

## 未保存修改

进入编辑页时记录初始 JSON；离开时比较当前 JSON：

- 无变化：直接退出。
- 有变化：提供取消、直接退出、保存并退出。
- 保存成功：返回列表并重新加载。
- 直接退出：磁盘内容不变。

任何重构都应保留这一防丢失行为。未来若引入自动保存，需要重新设计取消/撤销语义。

## 画像

- 通过 `image_picker` 从图库/文件来源选择。
- 选择时最大宽度 1600、质量 80，再以 Base64 存入 `Profile.PortraitBase64`。
- 本地列表和编辑页在内存解码；损坏 Base64 显示坏图标并允许清除。
- 画像随本地 JSON 保存，但永不上传到云端。专用 PDF 导入和导出会双向传递画像；不支持或损坏的 PDF 图片会被跳过，不影响其他角色数据。

## 删除

- 删除前显示不可撤销确认。
- 确认后只删除本地 `<id>.json`。
- 不删除云端备份，也不清理其他未知文件。
- 当前没有回收站或本地备份。

## PDF 入口

- 导入总是创建一个新的 `Character` 和新 UUID，解析后立即保存为本地 JSON。
- 导出使用当前角色填充内置模板。
- 操作期间显示不可关闭的加载对话框，完成后显示全局提示。
- 用户取消文件选择当前会被包装成“导入失败/用户取消保存”等错误，未来可改善为中性取消反馈。

详细契约见 [PDF 导入导出](PDF导入与导出.md)。

## 边界和验收

- 多个角色可以拥有相同显示名，但 ID 必须不同。
- 新建但未保存的角色不应出现在磁盘和列表中。
- 一个损坏 JSON 不应阻止其他角色出现。
- 旧版缺少新增字段的 JSON 应使用默认值成功读取。
- Windows 和 Android 编辑相同文件结构。
- 云端下载覆盖同 ID 本地角色后，列表重新加载应显示新数据并保留本地画像。
