# 云端备份

## 目标与非目标

云端功能为用户提供手动备份和跨设备恢复。它不提供传统账户、自动同步、多人共享、历史版本或图片备份。

## 首次使用

进入云端同步中心时：

1. 检查本地是否已有身份令牌。
2. 没有令牌时解释令牌含义，用户可以暂不开启或生成 UUID v4。
3. 生成后要求用户自行复制并妥善保存。
4. 使用该令牌构造带 `x-sync-token` 头的 Supabase 客户端。

用户可以在设置页手工输入其他设备的令牌，从而访问同一备份空间。

## 同步中心

### Android/窄屏

使用两个 Tab：云端角色（下载）与本地角色（上传）。

### Windows/宽屏

左右两栏同时展示云端下载和本地上传列表。

两种布局都支持刷新，网络或令牌错误显示可重试空状态。

## 云端列表

每项显示名称、ID 前四位、种族/职业和更新时间。若本地没有同 ID 角色，或云端时间晚于本地时间，标记“云端较新”。

该标记是提示，不是禁止条件。下载按钮始终按当前实现覆盖本地同 ID 数据。

## 上传

- 本地列表中的每个角色均可独立上传。
- 相同 `(id, sync_token)` 使用 upsert 覆盖。
- 若云端时间更晚，用户必须确认“强行上传”。
- 上传 payload 会清空画像字段。
- 上传成功后刷新云端时间，并回写本地角色。

## 下载

- 按 ID 读取当前令牌可见的云端行。
- 下载结果覆盖同 ID 本地 JSON，不提供自动合并或冲突副本。
- 如果本机已有同 ID 画像，则在覆盖前将该画像合并到下载对象。
- 本机没有同 ID 角色时，画像为空，因为服务器不保存图片。

## 删除和令牌更换

- 删除本地角色不影响云端备份。
- 当前 UI 不能删除云端角色。
- 生成新令牌不会迁移、删除或重新归属旧令牌的数据。
- 失去旧令牌意味着无法恢复该备份空间的访问。

这些行为是当前预期设计，应在用户提示中保持一致。

## 安全模型

身份令牌既是用户标识也是访问凭据。Supabase RLS 比较请求头与行内 `sync_token`：

```text
request header x-sync-token == characters.sync_token
```

该模型简单且适合无账户备份，但具有明确边界：

- 没有二次认证和令牌找回。
- 令牌泄露者可以访问对应角色数据。
- 数据不是端到端加密。
- `SharedPreferences` 不是高安全凭据库。

任何错误消息、分析日志和崩溃报告都不得包含令牌。

完整表与 RLS 契约见 [数据存储与云端备份](../数据存储与云端备份.md)。

## 离线和失败

- 云端页面失败不改变本地数据。
- 应用其他页面不需要有效令牌或网络。
- 上传失败不能更新本地 `updatedAt` 为伪造的云端成功时间。
- 下载应完成解析和画像合并后再覆盖本地文件。
- 未来应对下载覆盖提供更明确的时间/方向提示，但不能把手动备份改造成隐式自动同步。

## 验收

- 两个令牌的数据互不可见。
- 相同角色 ID 在不同令牌下可以独立存在。
- 上传永不包含画像；本地画像不被上传过程清空。
- 新设备下载成功但画像为空。
- 同设备下载保留本地画像。
- 云端较新上传会警告，取消后无写入。
- 无网络时本地角色和冒险功能不受影响。
