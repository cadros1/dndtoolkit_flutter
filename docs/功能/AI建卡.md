# AI 建卡

## 定位与边界

AI 建卡只用于创建新角色。它不会编辑已有角色，也不会给角色 JSON 增加 AI 来源字段。生成成功后得到普通的内存中 `Character`，进入现有编辑器；只有用户点击“保存并退出”才写入本地主要副本。

该功能是可选联网增强。角色列表、空白建卡、角色编辑、PDF、冒险状态和掷骰仍可离线使用。首次进入 AI 建卡时必须确认：输入会发送到第三方、可能产生费用、生成范围仅为 D&D 5E 2014 官方常规内容。

## AI 服务配置

用户保存的是具名配置，而不是单一协议。一个配置包含 UUID、配置名、服务类型、Base URL、模型名、思考开关和思考强度。

- 类型为 DeepSeek 时使用官方 Base URL；思考强度为 `high` 或 `max`。
- 类型为 OpenAI 协议时使用用户填写的 HTTPS Base URL；思考强度为 `low`、`medium`、`high`、`xhigh` 或 `max`。
- 配置元数据保存在 `SharedPreferences`；API Key 以配置 UUID 为键保存在 `flutter_secure_storage`。
- 编辑配置时 API Key 留空表示保留原值；删除配置同时删除密钥。
- 配置编辑页可通过 `/models` 获取服务端模型列表；获取成功后在弹窗的下拉菜单中选择并确认，模型名仍可手动填写，以兼容未实现该端点的服务。
- Android 的 API Key 输入使用普通可粘贴键盘，因此输入内容会直接显示。Android 必须保持输入建议标志开启但关闭自动纠错，避免 Flutter 引擎附加 `TYPE_TEXT_VARIATION_VISIBLE_PASSWORD` 后被小米等系统识别为密码框；Windows 仍提供显示/隐藏开关。
- 连接测试验证鉴权、模型、JSON 模式和思考参数，可能产生少量费用。

请求使用 `/chat/completions` 和 `response_format: {"type":"json_object"}`。不发送 `max_tokens` 或 `max_completion_tokens`，也不发送温度。长度截断的响应不能建卡。API Key、完整提示词、原始响应及模型思考内容不写日志或本地文件。

## 输入语义

总等级、AI 配置、属性生成方式和玩法偏好是必填项。“建卡要求”提供两种输入模式，“从你的想法生成”默认关闭：

- 开启“从你的想法生成”时，只显示必填的“角色描述”。模型根据这段描述选择职业与子职（若有）、种族与亚种（若有）、背景和阵营，适合不熟悉具体规则选项的用户。
- 关闭“从你的想法生成”时，显示职业、种族、背景和阵营四个必填输入框。四项均作为不可替换的硬约束，适合已有明确构筑目标的用户。
- 角色姓名不在建卡要求中指定，由模型在两种模式下生成。

“玩法偏好”在两种模式下始终显示，用于描述角色在战斗和冒险中的行为风格。模型必须据此选择装备、法术、职业特性和其它能力。

人物塑造按完整内容组控制，避免逐字段混写破坏连贯性：

- 外貌特征组包含年龄、身高、体重、眼睛、皮肤和头发。
- 个性与背景组包含个性、理想、纽带、缺陷、盟友与组织、所持物、附加特征、角色经历和背景故事。其中“所持物”是与背景故事有关的事物而非装备；“附加特征”是外观特征；“背景故事”是塑造人格的重大事件。
- 人物塑造中的所有具体输入框均为可选。组开关关闭时，本地原样写入用户已填写的内容，模型不会改写；开关开启时收起具体字段，只显示可选的“你的倾向”，由模型生成整组内容。
- “角色经历”仅存在于本地表单和标准 `Character` 映射中，不进入发送给模型的数据或系统提示词，也不属于 AI 响应 JSON schema。组开关关闭时，玩家填写的内容由本地原样写入；组开关开启或“无需添加”时，该字段保持为空。
- “无需添加”会收起并停止发送全部人物塑造输入，生成结果中的叙事与外貌字段为空；职业特性、专长、语言、装备和法术仍会生成。

## 属性生成

- 购点法使用 5E 2014 的 8–15 标准费用表，预算为 0–54。提交前验证预算可达，AI 基础属性必须恰好用完预算。
- 掷骰法在本机用安全随机源一次生成 1–10 组。每组有六个 `4d6dl1` 点数，页面只展示六个结果及总和。当前建卡页面会话内不能重掷；退出再进入才开始新会话。
- 给定点数组接收六个 3–18 的整数，顺序不绑定属性。
- 标准点数组固定为 `15, 14, 13, 12, 10, 8`。

AI 必须分别返回基础分配、种族加值、等级提升和最终值。本地验证基础数组/购点预算以及逐项加法；进入编辑器前会展示逐项的基础值、种族加值和等级提升，弹窗仅提供确认并进入编辑器的操作。项目不内置种族或职业资料库，因此具体加值是否符合所选内容仍需用户复核。中间分解不写入角色 JSON。

## 响应与失败

AI 响应使用独立 DTO 和固定 schema，不能提供角色 UUID、文件路径、更新时间、玩家名、画像或 API 配置。映射时由本地生成 UUID、熟练加值及新卡动态状态，并把生命、生命骰和法术位初始化为满值。

模型只需返回已知法术；映射层会按编辑器契约把 0–9 环分别补齐为固定数量的可编辑空位，不能让模型返回的法术数量缩短法术表。

职业等级之和、属性来源、字段类型、未知字段和集合长度均在本地校验。首次响应解析或校验失败时允许自动追加一次完整修复请求；仍失败则保留表单和已掷数组，向用户显示可恢复的中文错误。
