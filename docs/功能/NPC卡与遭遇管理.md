# NPC 卡与遭遇管理

## 状态与定位

第一步“本地 NPC 库与当前遭遇闭环”和第二步“Markdown 交换”已经实现；遭遇预设和云端备份仍是后续计划。本文同时记录当前能力和后续分步范围，描述功能状态时必须区分已经可用的前两步与尚未实现的第三、第四步。

功能面向 DM 在备团时维护 NPC 卡，并在跑团中管理 NPC 实例、集群先攻和生命值。它仍然是记录与计算工具，不自动判断攻击是否命中、豁免是否成功或战斗结果，也不引入玩家/DM 账户身份或权限系统。

一级导航已经提供“DM”，其下包含“NPC 库”和“当前遭遇”。用户界面不额外解释 NPC 一词的覆盖范围。

## 当前实现与本地数据

- `lib/models/dm_models.dart` 定义 NPC 卡、分类、卡片快照、NPC 实例、集群和唯一当前遭遇。
- `lib/services/dm_storage.dart` 将全部 DM 本地数据保存到应用文档目录的 `dm/dm_data.json`；该子目录与角色 `<UUID>.json` 分离，不会被角色扫描器误读。
- `lib/services/npc_markdown_service.dart` 负责 NPC Markdown v1 的确定性导出、SHA-256 校验、应用格式解析、任意 Markdown 尽力识别和平台文件交换；`lib/pages/dm/npc_markdown_import_page.dart` 负责逐文件预览与分类确认。
- 根对象使用 `DnDToolkit-DM: 2` 作为内部 JSON schema 标识，并继续读取版本 1。新增字段必须提供安全默认值；已发布字段不得无迁移地改名、删除或改变类型。客户端拒绝读取比自身更新的 schema，避免把未知字段回写丢失。
- 实例的 `CardSnapshot` 是创建时的完整 NPC 卡副本。删除或编辑 NPC 卡只影响模板库，不改变当前遭遇已有实例。
- 页面切换、应用进入后台/非活动状态和每次遭遇操作都会保存当前数据。DM 文件无法解析时页面提示错误并保留原文件，不会用空数据静默覆盖。

## 领域概念

```text
分类
└─ NPC 卡模板
   └─ 实例化
      ├─ 独立 NPC 实例：使用自己的先攻
      └─ 集群成员：使用集群先攻

遭遇预设（后续阶段）
└─ 创建一个新的当前遭遇
```

- **NPC 卡**：可重复使用的静态资料模板。
- **分类**：用户自行命名的 NPC 卡分组。第一版一张 NPC 卡只能属于一个分类。
- **NPC 实例**：从 NPC 卡创建、只属于当前遭遇的运行时副本。
- **集群**：共享一个先攻值的 NPC 实例集合，可以混合不同 NPC 卡创建的实例。
- **当前遭遇**：正在使用的唯一活动遭遇，保存实例、集群和动态生命值。
- **遭遇预设**：后续阶段提供的可复用配置，用于快速创建新的当前遭遇，不等同于运行中的遭遇状态。

## 最终计划功能集合

### NPC 库与分类

- 创建、编辑、复制、删除和搜索 NPC 卡。
- 按分类筛选 NPC 卡，并提供“全部”。
- 始终存在一个出现在分类管理中的“默认分类”；它不可删除，新卡自动归入该分类。
- 创建、重命名、排序和删除其他分类。删除分类时把其中 NPC 卡移动到“默认分类”，不得连带删除卡片。
- 第一版每张 NPC 卡只属于一个分类；多分类或标签仅在出现明确需求后另行设计。
- 从 NPC 卡直接添加一个或多个实例到当前遭遇，并提供自动命名结果供用户修改。

### NPC 卡字段

NPC 卡保存以下内容：

- 姓名。
- 分类。
- 体型与生物类型。
- 最大生命值。
- 护甲等级。
- 速度，自由文本，例如“5 尺，飞行 30 尺”。
- 力量、敏捷、体质、智力、感知、魅力六项属性值。
- 六项属性调整值；应用按 `floor((属性值 - 10) / 2)` 自动派生，只读展示，不允许手动更改。
- 豁免，多行自由文本。
- 技能，多行自由文本。
- 伤害易伤、伤害抗性、伤害免疫和状态免疫，分别使用一个独立的多行文本框。
- 感官，多行自由文本。
- 语言，多行自由文本。
- 挑战等级，自由文本，以兼容 `1/8`、`1/2`、`—` 和自制内容。
- 特性、动作、附赠动作、反应和传奇动作；每个分区由可排序的“名称 + 描述”条目组成，没有内容的可选分区在阅读界面隐藏。
- 备注。

除必要的数值边界外，上述内容不使用官方列表或封闭枚举，不内置规则原文、怪物资料库或构筑内容。

### NPC 实例

- 实例创建时复制 NPC 卡资料，此后与模板分离。
- 编辑或删除模板不得改变、删除已经存在的实例。
- 实例可以修改显示名称、当前生命值、临时生命值、先攻和自由文本备注。
- 实例使用模板的最大生命值，不允许提高或单独覆盖；需要更高最大生命值时应创建或复制一张新的 NPC 卡。
- 当前生命值限制在 0 到模板最大生命值之间；临时生命值是独立的非负数值，不计入当前生命值上限。
- 当前生命值恢复为正数或降至 0 不触发死亡豁免；NPC 实例不使用玩家角色的死亡豁免规则。
- 当前生命值一级页面只提供加、减和当前值编辑，不提供“受到 X 点伤害”“恢复 X 点生命”或预设变化量。
- 实例不提供结构化状态追踪。备注保持自由文本，不自动应用规则效果。
- 实例可以复制、移出遭遇以及在独立状态和集群之间移动，但不能反向覆盖原 NPC 卡。

### 集群先攻

- 用户可以创建并命名集群，为集群填写一个先攻值。
- 集群可以包含任意 NPC 实例，不要求成员来自相同 NPC 卡。
- 集群成员各自保存名称、当前生命值和临时生命值，但在先攻顺序中共同使用集群先攻。
- NPC 加入集群后不再使用独立先攻；移出集群后独立先攻留空，由用户重新填写。
- 独立 NPC 与集群都是同一级先攻单位，默认按先攻从高到低排列。
- 先攻相同时允许用户手动调整前后顺序；未填写先攻的单位排在列表底部。
- 空集群可以暂时保留。删除集群时必须让用户选择“成员转为独立 NPC”或“连同成员一起移出遭遇”。
- 本功能不追踪当前轮次或当前行动者，也不试图覆盖玩家角色的先攻记录。

### 当前遭遇

- 第一阶段和最终版始终只有一个正在运行的“当前遭遇”；后续的预设用于创建当前遭遇，不产生多个同时活动的遭遇。
- 当前遭遇在切换页面、应用进入后台和应用重启后继续保留。
- 结束遭遇会清空实例、集群和动态状态，需要二次确认；第一阶段不保留遭遇历史。
- 一级列表优先展示先攻、名称、AC、当前/最大生命值和临时生命值摘要。
- 当前生命值加减位于一级页面。临时生命值非零时应直接可见；设置或修改临时生命值位于实例二级菜单。
- 特性、动作和其他长文本进入实例详情，不挤占先攻列表。

### 最低限度掷骰

当前遭遇提供与 NPC 卡内容无绑定的通用掷骰入口：

- 骰面：D4、D6、D8、D10、D12、D20、D100。
- 次数：1、2、3、4、5、10。
- 用户直接填写总加值。
- 优势、正常、劣势三态。
- 不选择 NPC 属性、技能或动作，不从文本解析加值，也不提供动作快捷掷骰。
- 结果和日志仅存在于当前页面会话，不修改 NPC 或当前遭遇状态。
- 与现有自由掷骰一致，界面可以对任意骰面应用优势/劣势，但不得描述为 5E 对所有骰子的规则。

### 遭遇预设

最终功能集合需要包含遭遇预设，但不进入第一阶段：

- 创建、命名、复制、编辑和删除预设。
- 预设记录所用 NPC 卡、数量、默认实例命名和集群安排。
- 从预设创建当前遭遇时生成新的实例，当前生命值初始化为模板最大值，临时生命值初始化为 0。
- 编辑或删除预设不影响已经创建的当前遭遇。
- 从预设创建遭遇时，如当前遭遇非空，必须先明确确认替换。
- 预设不引入轮次或当前行动者追踪。

### 明确不做

- NPC 动作快捷掷骰或动作文本解析。
- 快速输入伤害/治疗变化量。
- 当前轮次和当前行动者追踪。
- NPC 结构化状态及其规则自动处理。
- AI 生成 NPC 草稿。
- 内置官方或第三方 NPC/怪物资料库。
- 自动判断命中、检定成功、豁免成功或战斗结果。
- 多人联机、共享战场或 DM/玩家权限系统。

## Markdown 导入导出

Markdown 是 NPC 卡当前使用的交换格式。详细兼容决策见 [ADR-0007](../架构决策记录/0007-NPC卡使用Markdown交换.md)。

### 应用导出格式

- 一个 Markdown 文件保存一张 NPC 卡，不保存实例、当前生命值、临时生命值、先攻、集群或遭遇状态。
- 文件头部包含两个非中文机器字段：`DnDToolkit-NPC` 格式标识和 `SHA256` 内容校验值。
- 除这两个字段外，所有字段名、标题和分区名均使用当前中文 UI 术语，以保证文件直接分发时可读。
- 文件不携带内部 ID；导入始终创建新 NPC 卡，允许同名卡共存，不静默覆盖已有卡片。
- 分类随 NPC 卡导出。导入时不存在的分类可在预览确认后创建，也可改为“默认分类”。
- 应用提供可导出的空白模板，供用户手工编写兼容文件。

示意结构：

```markdown
---
DnDToolkit-NPC: 1
SHA256: <64 位十六进制校验值>
名称: "哥布林"
分类: "地精部族"
体型与生物类型: "小型类人生物"
护甲等级: 15
最大生命值: 7
速度: "30 尺"
挑战等级: "1/4"
---

# 特性

## 条目 1
名称: "灵活逃脱"
描述: "特性说明……"

# 动作

## 条目 1
名称: "弯刀"
描述: "动作说明……"
```

导出器固定字段顺序；文本值使用 JSON 字符串转义，以稳定保存引号、反斜线、中文和多行文本。换行统一为 LF，UTF-8 不带内部 ID。固定 fixture 和契约测试覆盖 LF、CRLF、中文、多行文本、空字段和完整往返，不能只依赖宽松解析。

### 导入分支

1. **有格式标识且校验一致**：按应用格式读取，正常显示导入摘要。
2. **有格式标识但校验不一致**：标记为“文件在导出后被修改”，继续尝试解析，并在确认页列出缺失、改变和无法识别的内容。
3. **没有格式标识**：视为任意 Markdown，尽力根据中文标题、表格和常见文本结构识别；必须显示识别预览和未识别内容，不得静默创建近乎空白的 NPC 卡。

SHA-256 只用于判断文件内容是否与记录的校验值一致，不是数字签名，不能证明文件由可信应用生成或内容安全。导入错误和警告必须说明可恢复方式，不得因单个坏文件阻止其他文件导入。

### 当前文件交互

- Windows 导出使用系统保存对话框；Android 写入带时间戳的唯一临时文件，调起系统分享面板后尝试清理临时文件。
- NPC 卡菜单可以导出单张卡；NPC 库页面操作提供多文件导入和空白模板导出。当前不提供批量导出。
- 导入一次可选择多个 `.md` 或 `.markdown` UTF-8 文件，每个文件上限 2 MB。读取失败、空文件和近乎空白文件各自显示错误，不阻止其他文件进入预览。
- 预览页逐文件显示校验状态、识别摘要、缺失字段、警告和未识别内容。用户可取消选中任意文件，并为每张卡选择已有分类；导出分类不存在时可新建同名分类或改用“默认分类”。
- 确认导入始终生成新的 NPC 卡及条目 ID；名称相同也并存，不覆盖已有卡片。

## UI 规划

### 导航

- 移动端一级底部导航与桌面一级侧栏新增“DM”。
- “DM”内部使用“NPC 库 / 当前遭遇”二级切换；后续加入预设时应避免把二级入口继续堆叠成过多页签，可在 NPC 库或当前遭遇内提供预设入口。
- NPC 编辑和实例详情属于更深一级页面，不占用一级导航。

### NPC 库

移动端：

- 顶部依次为“NPC 库 / 当前遭遇”切换、搜索和分类筛选。
- 主体使用紧凑纵向卡片列表，卡片展示名称、分类、体型与生物类型和挑战等级，不展示 HP、AC、速度或“加入遭遇”按钮。
- 点击卡片进入编辑，更多菜单包含复制、导出、移动分类和删除；实例从“当前遭遇”的“添加 NPC”入口创建。
- 浮动按钮用于新建 NPC；导入、空白模板导出和分类管理位于页面更多菜单。

桌面端：

- 左侧展示“全部”“默认分类”和用户分类；右侧顶部展示搜索、排序、新建和导入。
- 单卡导出位于卡片更多菜单；空白模板导出位于右侧顶部页面操作菜单。
- 主体使用自适应卡片网格；窗口变窄时退化为单列列表和分类选择器。
- 分类的创建、重命名、排序和删除集中在分类管理界面。

### NPC 编辑

编辑分为三区：

1. 基础信息：名称、分类、体型与生物类型、最大 HP、AC、速度和挑战等级。
2. 属性与信息：带步进器的六维属性值、自动只读调整值、豁免、技能、感官、语言、伤害易伤、伤害抗性、伤害免疫和状态免疫；文本输入框最小高度为一行。
3. 特性与行动：特性、动作、附赠动作、反应、传奇动作和备注。

移动端使用可滚动分区页签和底部固定“保存并退出”；桌面端使用左侧分区导航和顶部保存。特性与行动使用可折叠、可上移/下移的“名称 + 描述”条目，拖拽不得成为唯一排序方式。离开未保存页面时沿用角色编辑器的取消、直接退出、保存并退出三种选择。

### 当前遭遇

移动端：

- 列表项是“先攻单位”：独立 NPC 是一个单位，集群也是一个单位。
- 集群标题显示先攻、名称和成员数，展开后逐个展示成员。
- 集群二级菜单提供“添加 NPC”，复用当前遭遇的批量添加与命名流程，并将新实例直接加入该集群。
- 实例行一级展示名称、AC、当前/最大 HP、临时 HP 摘要和当前 HP 加减。
- 点击实例进入全屏详情；短操作使用底部弹层，长动作文本不放入弹层。
- 页面顶部提供“添加 NPC”和“创建集群”；“掷骰”固定在页面底部并占据整行，结束遭遇放在更多菜单并二次确认。

桌面端：

- 左侧约三分之二展示先攻列表，右侧约三分之一展示选中实例或集群详情。
- 选中实例时展示属性、防御、感官、特性与行动；选中集群时展示名称、先攻和成员管理。
- 顶部常驻添加 NPC 和创建集群；“掷骰”固定在页面底部并占据整行。

两端都必须支持浅色/深色主题、大字号和键盘/触摸操作。紧凑布局通过折叠次要内容和进入详情实现，不通过缩小关键触控区域实现；当前 HP 加减等关键按钮保持至少约 44～48 logical pixels。

## 分步实现范围

### 第一步：本地 NPC 库与当前遭遇闭环

状态：已实现。

目标是让 DM 可以手工创建 NPC 卡并完成一次跑团管理；遭遇能力只实现唯一的当前遭遇，不实现预设。

范围：

- 独立的 NPC 卡、分类、NPC 实例、集群和当前遭遇数据。
- NPC 库、分类管理和 NPC 编辑页。
- 创建、编辑、复制、删除、搜索和分类筛选 NPC 卡。
- 从 NPC 卡单个或批量创建实例，自动命名并允许修改。
- 一个可跨页面和应用重启保留的当前遭遇。
- 独立先攻、混合成员集群先攻、同先攻手工排序。
- 当前生命值、临时生命值、实例备注和实例详情。
- 最低限度通用掷骰及页面会话日志。
- Windows 双栏和 Android 紧凑列表布局。
- 本步本身不包含 Markdown、遭遇预设、云端备份、遭遇历史或轮次追踪；Markdown 已在第二步实现。

### 第二步：Markdown 交换

状态：已实现。

- 导出单张 NPC 卡和空白模板。
- 读取格式标识并校验 SHA-256。
- 对校验不一致的应用文件继续尝试解析并明确报告。
- 对任意 Markdown 进行尽力识别，提供字段预览、警告、未识别内容和恢复路径。
- 支持一次选择多个文件导入；一个坏文件不阻止其他文件。
- 先保证单张导出；批量导出根据实际使用反馈增加。

### 第三步：遭遇预设

状态：尚未实现。

- 预设的创建、复制、编辑、删除和搜索。
- 配置 NPC 卡、数量、默认命名和集群安排。
- 从预设创建或替换当前遭遇。
- 从当前遭遇提取一个不含动态 HP 的预设草稿。
- 仍不增加轮次、当前行动者或自动规则处理。

### 第四步：云端备份

状态：尚未实现。

- 将 NPC 卡、分类和遭遇预设纳入现有手动云端备份体验。
- 当前遭遇、NPC 实例 HP、临时 HP 和集群运行状态保持本地，不做实时同步或多人协作。
- 备份必须保持本地为主要副本、手动上传下载和令牌隔离等现有产品语义。
- 在进入该阶段前单独确定冲突提示、删除行为和旧客户端兼容契约。

## 验收重点

- 模板、实例和预设互不产生未经用户确认的反向修改。
- 删除分类不删除卡片；删除模板不删除当前实例。
- 集群可以混合不同 NPC，成员 HP 和临时 HP 相互独立。
- 当前 HP 不超过模板最大 HP，临时 HP 不改变当前 HP 上限。
- 切换页面、后台和重启后当前遭遇不丢失。
- 没有当前轮次、动作快捷骰或自动规则判定的隐式行为。
- Markdown 校验结果、解析警告和未识别内容对用户透明。
- Android 小屏能同时查看多个先攻单位，所有关键触控目标可可靠点击；Windows 可以高效使用键盘和双栏详情。
- Windows 在 720/1024 等响应式断点之间反复切换时不得读取到写入中的 DM 数据，也不得显示加载失败。
