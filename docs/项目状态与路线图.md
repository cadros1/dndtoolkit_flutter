# 项目状态、已知限制与路线图

本文件区分已实现能力、已确认限制、技术债和未来计划。路线图表示方向，不等同于已承诺的版本或日期。

## 当前正式范围

- 规则：D&D 5E 2014。
- 平台：Windows、Android。
- 发布：GitHub Releases。
- Windows 产物：Inno Setup 6 制作的 EXE 安装包。
- Android 产物：APK。
- 数据：本地 JSON 主副本、专用 PDF 交换、Supabase 手动云备份。
- 联网：云备份、GitHub 更新检查、外部链接和用户主动触发的 AI 建卡。

## 已实现

### 角色与 PDF

- 创建、编辑、浏览和删除多个角色。
- 五个角色编辑分区和未保存退出确认。
- 本地画像选择、显示和清除。
- 专用中文 PDF 导入和导出。
- PDF 按钮画像正式导入、导出、失败回退及可移植专项测试。

### 冒险

- 多角色选择。
- HP、临时 HP、生命骰、钱币、法术位快捷修改。
- AC、先攻、速度和法术列表查看。
- 属性、豁免、技能、先攻、武器命中和自由掷骰，以及带持久进度的专用死亡豁免 Card。
- 优势/正常/劣势、多次投掷和会话内日志。

### 数据与云端

- 按 UUID 文件名保存本地 JSON。
- 坏文件跳过，不阻止其他角色加载。
- UUID v4 身份令牌生成、复制、输入和替换。
- Supabase RLS 按 `x-sync-token` 隔离数据。
- 手动上传、下载、云端较新提示和上传覆盖确认。
- 上传剔除画像，下载合并本机同 ID 画像。

### 应用基础

- Material 3 浅色/深色主题。
- Windows/Android 响应式导航和布局。
- GitHub Release 版本检查、红点、说明和外部下载跳转。
- PolyForm Noncommercial 1.0.0 和第三方开源许可入口。

### AI 建卡

- 具名 DeepSeek/OpenAI 协议配置、系统安全存储 API Key、连接测试和思考参数。
- 5E 2014 新角色引导表单、人物塑造省略、购点/本地掷骰/给定/标准属性数组。
- 设计构筑方案、细化构筑方案、计算衍生数值和塑造人物四阶段生成；第一阶段按明确/自由模式使用独立提示，第四阶段按外貌/人物设定的实际生成范围使用三套最小提示；用户确认并可分项修改构筑方案，后三阶段自动执行。
- 各阶段独立 JSON 白名单、10 分钟生成超时、生成用时显示、一次修复、失败阶段重试、属性来源与衍生数值组成校验。
- AI 建卡不修改已有角色，不改变角色 JSON 契约，也不影响核心离线能力。

### DM：NPC 卡与当前遭遇

- 一级“DM”入口及“NPC 库 / 当前遭遇”二级切换。
- 独立本地 NPC 卡、单分类、完整字段编辑、搜索、复制、删除、移动分类和批量实例化。
- 实例使用创建时卡片快照，与模板后续编辑/删除隔离。
- 唯一当前遭遇、独立先攻、可混合不同 NPC 的集群先攻、同先攻手工排序和重启保留。
- 当前/临时生命值、实例备注与详情、实例复制/移动/移出、结束遭遇确认。
- D4/D6/D8/D10/D12/D20/D100、1/2/3/4/5/10 次、总加值和优势/正常/劣势的会话通用掷骰。
- 单张 NPC 卡与空白模板 Markdown 导出、SHA-256 校验、修改文件报告、任意 Markdown 尽力识别、逐文件预览和多文件导入。
- Windows NPC 库/遭遇双栏与 Android 紧凑列表；不包含批量导出、遭遇预设、云端备份、历史或轮次追踪。

## 已废弃

### 局域网与 WPF 同步

`LanSyncService`、设备发现页和传输页已经由云端备份取代，仅保留历史参考。它们不属于当前功能，也不应继续扩展。未来清理前可保留 git 历史，不需要长期在生产代码中保留不可达实现。

### 非目标平台

iOS、macOS、Linux、Web 目录是 Flutter 模板遗留，不构成支持承诺。代码中个别 iOS 分支同样不改变此结论。

## 已知问题与限制

### P0：数据与发布风险

1. **损坏 JSON 没有用户提示**：当前只输出到 `stderr`，尚未达到“提示并跳过”的目标。
2. **没有 schema version 和迁移层**：模型虽有默认值兼容缺字段，但无法管理改名或类型变化。
3. **本地保存非原子且无备份**：进程或磁盘异常可能产生损坏文件。
4. **Android release 配置不完整**：仍使用默认 `applicationId` 和 debug signing。
5. **最低平台版本未固定**：Android 继承 Flutter 默认值；Windows 仅有 manifest 的 Windows 10/11 声明，缺少测试矩阵。

### P1：功能契约和测试

1. **PDF 动态状态非完整 round trip**：当前 HP、生命骰、剩余法术位会按满值处理；临时 HP 不导出，死亡豁免不映射。
2. **PDF 画像兼容范围有限**：当前仅支持常见 JPEG 和部分 8 bit PNG 结构，且底层实现依赖固定版本的 PDF 库内部接口。
3. **旧数据无 `updatedAt` 上传风险**：冲突无法比较，上传存在非空断言失败可能。
4. **冲突依赖客户端时钟**：设备时间偏差会导致错误的新旧判断。
5. **冒险页保存时序分散**：部分状态立即保存，HP/生命骰依赖生命周期保存；异步调用没有统一排队。
6. **核心文件过大**：冒险页和 PDF 服务修改面宽，缺少纯规则层和可替换边界。
7. **用户文案和元数据陈旧**：当前 README 仍提到 iOS、WPF/LAN 和旧路线，关于页写成仅面向 Players，`pubspec.yaml` 仍使用 Flutter 默认描述；应在后续用户文档/发布整理任务中统一，但本次按要求不修改 README。

### 已确认的产品限制

以下不是待修复 bug：

- 云端不保存画像，预计长期如此。
- 云端备份由用户手动上传/下载，不自动同步。
- 下载按同 ID 覆盖本地；上传云端较新时警告。
- 本地删除不删除云端，当前没有云端删除入口。
- 令牌丢失无法找回，生成新令牌不迁移旧数据。
- PDF 只兼容内置自制中文模板。
- 普通掷骰只展示，不判断成功失败或修改状态；专用死亡豁免按固定规则更新其进度，自然 20 恢复 1 点生命值。
- 不内置职业、种族、法术、专长和规则原文。

## 路线图

### 第一阶段：可靠性和可维护性

- 为角色 JSON 增加兼容的 `SchemaVersion` 和逐版本迁移框架。
- 损坏文件向用户显示文件级提示，同时保留并跳过。
- 使用临时文件 + 原子替换保存，并提供可恢复备份。
- 建立旧 JSON、完整 PDF、掷骰计算和云端 RLS 的可移植测试。
- 明确无 `updatedAt` 角色的上传策略，并降低设备时钟依赖。
- 拆分冒险页中的规则计算与 UI，统一冒险状态保存队列。

### 第二阶段：发布工程

- 固定并验证 Windows/Android 最低版本。
- 设置正式 Android application ID、release signing 和密钥管理。
- 将 Inno Setup `.iss` 脚本和发布清单纳入仓库。
- 建立两端 release build 和基础 smoke test 自动化。
- 完成从 GitHub Release 获取、下载、校验和引导安装的应用内更新。
- 为 Windows 和 Android 分别设计安全回滚与升级失败恢复。

“应用内更新”不等于静默安装。实现前需确认平台安全限制、签名、hash/signature 校验、用户授权和数据兼容。

### 第三阶段：5R（5E 2024）兼容

- 在数据模型中显式记录规则版本，同时让无版本旧角色默认为 5E 2014。
- 识别 5E 2014 与 5R 的字段、术语和计算差异。
- UI 能选择或展示角色规则版本。
- 规则计算按版本分派，不能全局替换 2014 行为。
- PDF 模板如不兼容，应新增独立模板和映射，不覆盖现有契约。

### 长期：大型功能

- 多人联机跑团。
- 多语言支持。

这些能力放在路线图末端，因为会显著影响账户/身份、权限、实时通信、内容本地化、数据模型和测试范围。开始前必须分别建立产品规格和 ADR，不能基于现有云备份令牌直接扩展成多人鉴权系统。

### NPC 卡与遭遇管理后续阶段

第一步本地闭环和第二步 Markdown 交换已经实现；后续阶段尚无已承诺版本或日期。该功能不依赖多人联机、账户身份或权限系统，完整规格见 [NPC 卡与遭遇管理](功能/NPC卡与遭遇管理.md)。

分步范围：

1. **本地 NPC 库与当前遭遇闭环（已实现）**：分类、NPC 编辑、实例化、混合集群先攻、当前/临时 HP、最低限度掷骰，以及 Windows/Android 响应式页面；只提供一个当前遭遇，不提供预设。
2. **Markdown 交换（已实现）**：应用格式的标识和 SHA-256 校验、修改文件报告、任意 Markdown 尽力识别、逐文件预览和多文件导入；先提供单张导出。
3. **遭遇预设**：保存 NPC 数量、默认命名和集群安排，并据此创建或替换当前遭遇；不增加当前轮次或当前行动者。
4. **手动云端备份**：备份 NPC 卡、分类和预设；当前遭遇及其实例动态状态继续只保存在本地。

明确排除动作快捷掷骰、伤害/治疗变化量快捷输入、结构化状态规则、AI 生成 NPC、内置怪物资料库和自动战斗判定。

## 明确不在路线图中的默认假设

除非未来重新决策，否则不假设会加入：

- 内置官方或第三方规则全文。
- 内置职业、种族、法术、专长数据库。
- 传统邮箱/密码账户。
- 云端画像存储。
- iOS、macOS、Linux 或 Web 支持。
- 恢复已废弃的局域网/WPF 同步。
