# UI、响应式布局与平台范围

## 正式平台

| 平台 | 状态 | 主要使用场景 |
| --- | --- | --- |
| Windows | 正式支持 | 大屏、鼠标键盘下集中编辑角色卡和管理文件 |
| Android | 正式支持 | 跑团中触摸操作、状态查看和快捷检定 |
| iOS | 不支持 | 目录和少量条件分支是 Flutter 模板/历史遗留 |
| macOS | 不支持 | 仅保留生成目录 |
| Linux | 不支持 | 仅保留生成目录 |
| Web | 不支持 | 仅保留生成目录 |

不要因为存在平台目录或 `Platform.isIOS` 分支，就在用户文档中宣称支持该平台。

## 响应式断点

共享断点位于 `lib/widgets/app_ui.dart`：

- `kAppDesktopBreakpoint = 720`
- `kAppWideBreakpoint = 1024`

一级导航、角色列表、角色编辑和云端中心主要以 720 为桌面分界。冒险检定中心弹层另以屏幕宽度 900 区分桌面对话框和移动端 bottom sheet。组件内部还根据自身可用宽度使用 360、380、420、430、500、520、560、620、720 等局部布局阈值。

这些阈值基于 logical pixels，不等同于操作系统设备型号。修改共享断点时要检查所有引用页面，不要只看 `MainScreen`。

## 一级导航

- 移动布局：底部 `NavigationBar`，入口为角色、冒险、更多。
- 桌面布局：左侧 `NavigationRail`，入口相同。
- “更多”入口可以显示新版本红点。
- 页面切换会销毁旧页面并创建新页面，以重新读取数据并触发冒险页离开保存。

## 角色编辑布局

- 移动端：顶部可横向滚动的五个 Tab，底部固定“保存并退出”。
- 桌面端：236 像素侧栏选择五个分区，内容最大宽度 880，顶部保存按钮。
- 五个分区：基础信息、技能豁免、冒险信息、人物设定、施法信息。
- 离开存在未保存修改时，应提供取消、直接退出、保存并退出三种选择。

Windows 与 Android 共享同一模型和字段，不允许某端保存另一端无法读取的平台专属结构。

## 冒险与检定布局

- 概览区在桌面限制最大宽度 980。
- 显示角色选择、HP、生命骰、AC、先攻、速度、钱币和法术入口；符合条件时在信息 Card 与“进行检定”之间显示死亡豁免 Card。
- 死亡豁免 Card 在宽屏横向展示两侧进度与中央结果，窄屏或大字号下重排；可见圆点较小，但每个点按区域至少 44 logical pixels。
- 检定中心在 Android/窄屏使用可拖动 bottom sheet；宽屏使用对话框，左侧控制、右侧日志。
- 触摸目标应维持至少约 44～48 logical pixels，尤其是 HP、法术位和钱币增减按钮。

## 视觉系统

项目使用 Material 3，系统主题自动选择浅色或深色模式。

### 核心颜色

- 浅色主色：`#6D3BEF`
- 深色主色：`#A78BFA`
- 浅色背景：`#FAF8FF`
- 深色背景：`#14111F`
- 成功：`#15803D`
- 警告：`#D97706`
- 信息：`#2563EB`

### 字体

- 应用主题使用 `NotoSansSC`，常规和粗体资源位于 `assets/fonts/`。
- PDF 中文写入使用 `simsun.ttc`。
- 身份令牌显示使用 monospace。

### 共享组件

- `AppPanel`：圆角表面、边框和轻阴影。
- `AppPageHeader`：页面头部摘要与操作区。
- `AppSectionTitle`：分区标题、说明和尾部操作。
- `AppEmptyState`：空数据或不可用状态。
- `AppLoadingState`：统一加载状态。
- `AppStatPill`：紧凑状态值。
- `AppSettingsTile`：设置/更多页入口。

优先复用共享组件和主题语义色，不在页面中建立新的平行视觉体系。

### 设置页层级

- “设置”是可继续扩展的一级页面，只展示设置分类和入口。
- 身份令牌的用途说明、当前令牌与更换操作集中在“云端备份 > 身份令牌”二级页面。
- 更换或重新生成已有令牌时，确认弹窗必须说明本地角色不受影响、旧备份不会被删除，并要求用户确认已保存当前令牌。
- 当前令牌使用 monospace 明文展示；复制操作只复制已经保存的令牌，不复制尚未确认的输入。
- AI 服务配置位于“设置 > AI 建卡 > AI 服务配置”二级页面，也可从没有可用配置的 AI 建卡页直接进入；列表展示具名配置而非协议，新建/编辑页逐步展示 Base URL、API Key 和思考强度。
- AI 建卡长表单使用 840 像素最大内容宽度、分区面板和渐进展开；移动端所有关键操作使用 Material 触控组件，不能依赖悬停。

## 平台文件行为

| 行为 | Windows | Android |
| --- | --- | --- |
| 角色 JSON | 应用文档目录 | 应用文档目录 |
| PDF 导入 | 原生文件选择 | 系统文件选择 |
| PDF 导出 | 原生保存对话框 | 临时文件后调用系统分享 |
| 画像选择 | 文件/图片 picker 的平台实现 | 系统图库 |
| 更新 | 浏览器打开 GitHub Release | 浏览器打开 GitHub Release |
| AI API Key | Windows 系统安全存储 | Android Keystore 支持的安全存储 |
| 安装 | Inno Setup 6 制作的 EXE | APK |

## 可访问性和交互要求

当前代码已广泛提供 tooltip、Material 语义组件和浅/深色主题，但尚无系统性无障碍测试。新 UI 至少应满足：

- 图标按钮提供 tooltip 或可读语义。
- 不能只依赖颜色表达云端较新、成功、失败或危险操作。
- 支持系统字体缩放，避免固定高度截断关键文字。
- 表单有 label，错误信息说明原因与恢复动作。
- Windows 可通过键盘聚焦关键操作；Android 触摸区域不应过小。
- 死亡豁免成功、失败、稳定、死亡和自然 1/20 均使用文字、图标、边框或数值共同表达，不能只依赖颜色。
- 窄屏、横屏、桌面窗口缩放时不产生溢出。

## 平台版本现状

- Windows manifest 声明 Windows 10/11 兼容，但项目尚未在文档或自动化中锁定和验证明确的最低 build。
- Android `minSdk`、`targetSdk` 和 `compileSdk` 继承当前 Flutter 工具链默认值，没有在项目中固定数字。

在发布文档中不要声称未经测试的最低版本。路线图应先确定支持矩阵，再在构建配置、CI 和手工设备测试中固定它。
