# 测试策略

## 目标

测试优先保护真实用户数据、5E 计算、PDF 固定契约、云端隔离和 Windows/Android 关键流程。UI 像素细节可以迭代，但数据丢失、跨令牌访问或旧角色无法读取属于高风险回归。

## 当前测试基线

| 文件 | 当前覆盖 |
| --- | --- |
| `test/widget_test.dart` | 移动尺寸下应用启动及一级导航文字 |
| `test/cloud_sync_service_test.dart` | 云端摘要从 JSONB Map/JSON 字符串解析，以及无效数据异常 |
| `test/pdf_button_icon_test.dart` | PDF 按钮画像提取、替换和 PNG/JPG/灰度透明图处理 |
| `test/ai_character_models_test.dart` | 购点、4d6dl1、属性来源/加法、角色经历本地映射及 AI 草稿白名单映射 |
| `test/ai_config_repository_test.dart` | 具名配置、密钥隔离、保留与删除 |
| `test/ai_character_service_test.dart` | DeepSeek/OpenAI 协议参数、JSON 模式及不发送 token 上限 |
| `test/ai_service_config_edit_page_test.dart` | Android 普通 API Key 输入与弹窗模型选择 |
| `test/ai_settings_navigation_test.dart` | 设置页 AI 服务配置入口与空状态 |
| `test/ai_character_creation_page_test.dart` | 建卡要求双模式、玩法偏好、人物塑造折叠、退出确认及生成后确认交互 |

当前不足：

- PDF 测试使用开发者个人绝对路径，大部分环境只能 skip。
- 没有领域模型兼容 fixture。
- 没有掷骰加值的单元测试。
- 没有本地坏文件 UI 提示测试。
- 没有 Supabase RLS 跨令牌集成测试。
- 没有 Windows/Android 集成测试或发布 smoke test。

## 分层策略

### 领域单元测试

应覆盖：

- 属性修正值，包括 1、8、9、10、11、12、20 等边界。
- 六项豁免的熟练与未熟练。
- 十八个技能的属性关联和熟练加值。
- 先攻、死亡豁免和武器命中加值。
- 缺字段旧 JSON 使用默认值。
- JSON → Character → JSON round trip。
- 未来 schema migration 的逐版本 fixture。

随机骰子逻辑目前嵌在页面中。要稳定测试，应先把“给定骰值如何选择优势/劣势并加总”提取为纯函数，或注入随机源。

### 本地存储测试

使用临时目录或可注入目录，而不是用户真实应用目录：

- 保存生成 `<id>.json`。
- 普通保存更新 UTC `updatedAt`。
- 下载保存保留远端 `updatedAt`。
- 一个损坏文件不阻止其他角色加载。
- 非角色 JSON 被跳过。
- 目标行为：UI 能收到失败文件摘要并提示。
- 写入失败不破坏原文件；实现原子写入后增加故障测试。

### PDF 契约测试

在 `test/fixtures/` 放入经过授权且脱敏的最小模板/样例：

- 全字段 PDF → Character 映射。
- Character → PDF → Character 的稳定字段 round trip。
- 中文文本和嵌入字体。
- 十八技能、六豁免复选框。
- 0～9 环法术、准备状态和法术位。
- 三个武器槽。
- JPEG、RGB PNG、灰度 PNG、透明度和损坏图片。
- 用户取消导入/导出。

测试必须明确 PDF 不保留哪些冒险动态状态，避免误把当前满值重置行为当成完整 round trip。

### 云端与 RLS 测试

使用隔离的测试 Supabase 项目或可清理的测试令牌：

1. Token A 上传角色，A 可以查询和覆盖。
2. Token B 无法查询、更新或删除 A 的行。
3. B 可以上传相同角色 ID，并形成联合主键下的独立记录。
4. 空头、错误头和非 UUID 头不能访问数据。
5. 上传 payload 的 `PortraitBase64` 为空，而本地对象画像保持不变。
6. 下载同 ID 时保留本地画像；新设备下载时画像为空。
7. 云端较新上传触发确认；取消不写入。
8. 下载覆盖和本地/云端删除互不联动。
9. `updatedAt == null` 的旧数据有明确处理结果。

不得在 CI 输出 token 或完整角色 JSON。

### Widget 与集成测试

关键流程：

- 无角色空状态 → 新建 → 填写 → 保存 → 列表出现。
- 编辑后返回：取消、丢弃、保存三条路径。
- PDF 导入成功和失败提示。
- 选择不同角色进入冒险页。
- HP、生命骰、钱币、法术位修改后重新进入仍存在。
- 检定结果只进入日志，不修改角色。
- 清空日志只影响当前会话。
- 无令牌进入云端中心的生成/暂不开启流程。
- 无网络时本地页面可用，云端与更新给出非阻塞反馈。

## 响应式回归矩阵

至少覆盖以下 logical size：

| 场景 | 建议尺寸 |
| --- | --- |
| 小型 Android 竖屏 | 360 × 640 |
| 常见 Android 竖屏 | 390 × 844 |
| Android 横屏 | 844 × 390 |
| 断点下方 | 719 × 900 |
| 断点上方 | 720 × 900 |
| Windows 常规窗口 | 1280 × 720 |
| Windows 高 DPI/大窗口 | 1920 × 1080，配合系统缩放 |

检查 overflow、文本缩放、键盘遮挡、bottom sheet、Tab 滚动和触摸目标。

## 手工平台检查

### Windows

- 新装和覆盖安装。
- 文件选择与 PDF 保存位置。
- 中文路径和角色名作为文件名。
- 窗口缩放、最大化、最小化和高 DPI。
- 外部浏览器跳转。
- Inno Setup 升级后本地角色是否保留。

### Android

- 首次安装、升级安装和权限行为。
- 系统文件选择、图库与分享 sheet。
- 后台、锁屏、旋转和进程恢复时的状态保存。
- 无网、弱网和网络切换。
- APK 签名升级兼容。

## 任务完成标准

最低要求：

```powershell
dart format --set-exit-if-changed lib test
flutter analyze
flutter test
```

涉及平台插件、构建配置或发布时再运行：

```powershell
flutter build windows --release
flutter build apk --release
```

若某测试因为现有 fixture 或环境限制无法运行，交付时必须明确说明，不能把 skip 当作已验证通过。
