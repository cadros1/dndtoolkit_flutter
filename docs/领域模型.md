# 领域模型与规则计算

## 模型原则

`Character` 是本地文件、PDF、冒险页和云端备份共享的核心数据结构。对象及子对象均为可变 Dart class，通过 `json_serializable` 转换为 PascalCase JSON。

模型服务于开放式角色卡，而不是角色构筑器：职业、种族、背景、法术名称、能力说明等保持自由文本，不对第三方或自制内容做枚举限制。

## 对象树

```text
Character
├─ id: String
├─ filePath: String?          # 仅运行时，不序列化
├─ updatedAt: DateTime?
├─ profile: Profile
├─ attributes: Attributes
├─ combat: CombatStats
├─ proficiencies: Proficiencies
├─ roleplay: Roleplay
├─ spellbook: Spellbook
│  └─ allSpells: List<SpellLevelGroup>
│     └─ spells: List<Spell>
├─ weapons: List<Weapon>
└─ inventory: Inventory
```

## Character 根对象

| 字段 | JSON | 默认值 | 语义 |
| --- | --- | --- | --- |
| `id` | `Id` | UUID v4 | 跨本地、PDF 导入后保存和云备份识别角色的稳定 ID |
| `filePath` | 不序列化 | `null` | 预留运行时文件路径；当前存储实现没有赋值 |
| `updatedAt` | `UpdatedAt` | `null` | 最近一次本地保存或云端返回的 UTC 时间，用于冲突提示 |
| `profile` | `Profile` | `Profile()` | 基础身份、成长、外貌和画像 |
| `attributes` | `Attributes` | 六项均为 10 | 六项属性及计算修正值 |
| `combat` | `Combat` | `CombatStats()` | 战斗基础值和跑团动态状态 |
| `proficiencies` | `Proficiencies` | 全部未熟练 | 豁免、技能、其他熟练和语言 |
| `roleplay` | `Roleplay` | 空文本 | 个性、背景和设定 |
| `spellbook` | `Spellbook` | 0～9 环默认结构 | 施法参数、法术位和法术名称 |
| `weapons` | `Weapons` | 三个空武器槽 | 武器命中加值与伤害说明 |
| `inventory` | `Inventory` | 钱币 0、装备空 | 装备文本与五类钱币 |

同一身份令牌下，相同 `id` 代表同一角色；不同令牌可以各自拥有相同 `id`，云端联合主键仍能隔离。

## Profile

| 分组 | 字段 | 默认值/说明 |
| --- | --- | --- |
| 身份 | `characterName`, `playerName`, `race`, `classAndLevel`, `background`, `alignment` | 自由文本 |
| 成长 | `experiencePoints` | `0` |
| 规则数值 | `proficiencyBonus` | `2`，由用户维护 |
| 辅助数值 | `passivePerception` | `10`，当前不是自动派生字段 |
| 状态 | `inspiration` | 字符串而非 bool，兼容 PDF 自由填写 |
| 外貌 | `age`, `height`, `weight`, `eyes`, `skin`, `hair` | 自由文本，避免限定单位 |
| 画像 | `portraitBase64` | 空字符串；保存在本地 JSON，云端必须清空；当前 PDF 主流程尚未映射 |

不要擅自把职业、等级、种族或阵营拆成封闭枚举。若未来需要结构化数据，应保留旧自由文本读取和迁移路径。

## Attributes

六项属性为整数，默认均为 10：`strength`、`dexterity`、`constitution`、`intelligence`、`wisdom`、`charisma`。

属性修正值不序列化，由 getter 实时计算：

```text
modifier = floor((score - 10) / 2)
```

例如 9 → -1，10 → 0，11 → 0，12 → +1。使用向下取整对负数尤其重要。

当前 UI 未给属性值设置规则上限或下限。新增校验前应考虑自制内容兼容，不能仅按标准角色常见范围截断。

## CombatStats

### 基础与动态状态

- `armorClass`：护甲等级，默认 10。
- `initiative`：完整先攻加值，默认 0；检定中心直接使用，不额外加敏捷修正。
- `speed`：自由文本，保留单位和多种移动速度表达。
- `hitPointsMax`：最大生命值。
- `hitPointsCurrent`：当前生命值，可由冒险页直接修改。
- `hitPointsTemp`：临时生命值，可由冒险页直接修改。
- `hitDiceTotal`、`hitDiceCurrent`：自由文本，兼容 `4d8` 等表达。
- `deathSuccess1..3`、`deathFail1..3`：死亡豁免复选状态；当前编辑/冒险 UI 尚未暴露完整操作入口。
- `attacksAndSpellcastingNotes`：其他攻击/法术备注。
- `ability`：特殊能力自由文本。

当前冒险页允许 HP 输入负数或高于最大值，生命条在展示时才将当前值和临时值按非负数处理。不要把展示上的 clamp 误认为数据约束。

## Proficiencies

六个豁免熟练和十八个 5E 2014 技能熟练均为 bool。当前模型只表达“未熟练/熟练”，不表达半熟练、专精或临时加值；额外情况可以通过检定中心的“额外加值”临时处理，但不会持久化。

### 技能与属性关系

| 属性 | 技能（当前 UI 术语） |
| --- | --- |
| 力量 | 运动 |
| 敏捷 | 体操、巧手、隐匿 |
| 智力 | 奥秘、历史、调查、自然、宗教 |
| 感知 | 驯兽、洞悉、医药、察觉、生存 |
| 魅力 | 欺瞒、威吓、表演、游说 |

注意：PDF 字段内部使用“杂技、躲藏”等名称，UI 使用“体操、隐匿”。映射以 `PdfDataService._skills` 和 `_setSkill/_getSkill` 为准，不应仅凭显示文本改字段名。

## Roleplay

- `personalityTraits`：个性。
- `ideals`：理想。
- `bonds`：纽带。
- `flaws`：缺陷。
- `characterBackstory`：背景故事。
- `alliesAndOrganizations`：盟友与组织。
- `additionalFeaturesAndTraits`：UI 与 PDF 共用的“附加特征”正式字段。
- `treasure`：UI 当前显示为“所持物”。
- `characterExperience`：角色经历。

`Feat+Traits` 在 PDF 导入和导出时都映射到 `additionalFeaturesAndTraits`。

## Spellbook

- `spellcastingClass`：施法职业，自由文本。
- `spellcastingAbility`：施法关键属性，自由文本。
- `spellSaveDC`：法术豁免难度。
- `spellAttackBonus`：法术攻击加值。
- `allSpells`：默认包含 0～9 环十个 `SpellLevelGroup`。

每个法术环组包含：

- `level`：0 表示戏法，1～9 表示法术环位。
- `totalSlots`：总法术位；戏法通常保持 0。
- `remainSlots`：冒险中剩余法术位。
- `spells`：固定数量的空白法术槽，每项含名称和是否准备。

默认法术行数量依次为：

```text
0～9 环：[8, 12, 13, 13, 13, 9, 9, 9, 7, 7]
```

该固定容量与专用 PDF 字段数量一致。改变数量必须同时验证 PDF 映射和旧 JSON。

## Weapon 与 Inventory

`Weapon`：

- `name`：自由文本。
- `attackBonus`：完整命中加值；武器检定直接使用。
- `damage`：伤害与类型自由文本，应用不解析或掷伤害骰。

`Inventory` 保存 CP、SP、EP、GP、PP 五种钱币整数和 `equipmentText`。当前没有自动换算、重量或负值约束。

## 检定计算契约

### 属性检定

```text
d20 + 对应属性修正值 + 用户临时额外加值
```

### 豁免检定

```text
d20 + 对应属性修正值
    +（若该豁免已熟练，则加 proficiencyBonus）
    + 用户临时额外加值
```

### 技能检定

```text
d20 + 技能关联属性修正值
    +（若该技能已熟练，则加 proficiencyBonus）
    + 用户临时额外加值
```

### 其他检定

- 先攻：`d20 + combat.initiative + 额外加值`。
- 死亡豁免：`d20 + 额外加值`；结果不修改死亡豁免复选状态。
- 武器命中：`d20 + weapon.attackBonus + 额外加值`。
- 自由检定：用户选择 D4/D6/D8/D10/D12/D20/D100，再加临时额外加值。

优势取两次同面骰较高值，劣势取较低值。当前 UI 是单选状态，不存在“优势和劣势同时设置”的数据状态。

自然 20/1 只产生绿色/红色显示标记。应用不应据此自动判定所有属性检定或豁免成功/失败，也不应自动更新角色状态。

## JSON 兼容契约

- 字段名为 PascalCase，视为已发布的外部数据契约。
- 新增字段必须有默认值，并验证缺少该字段的旧 JSON 可读取。
- 禁止直接删除或改名已发布字段；需要先实现兼容读取和迁移。
- 字段类型变化必须接受旧类型或提供显式迁移和错误提示。
- 未识别的额外 JSON 字段目前会被忽略，这有利于向前兼容。
- 根对象必须有非空字符串 `Id`，并至少出现一个角色分区才会被本地扫描器视为角色文件。
- 当前没有 `SchemaVersion`。加入版本号是近期技术路线，但不能让无版本旧文件失效。
- 日期统一以 ISO 8601 字符串保存；本地保存写入 UTC 时间。

示例骨架：

```json
{
  "Id": "00000000-0000-4000-8000-000000000000",
  "UpdatedAt": "2026-08-08T12:00:00.000Z",
  "Profile": {
    "CharacterName": "示例角色",
    "ProficiencyBonus": 2,
    "PortraitBase64": ""
  },
  "Attributes": {
    "Strength": 10,
    "Dexterity": 10,
    "Constitution": 10,
    "Intelligence": 10,
    "Wisdom": 10,
    "Charisma": 10
  },
  "Combat": {},
  "Proficiencies": {},
  "Roleplay": {},
  "Spellbook": { "AllSpells": [] },
  "Weapons": [],
  "Inventory": {}
}
```

该示例只展示形状，不是推荐直接用空对象构造生产数据；完整默认值由生成的反序列化逻辑提供。
