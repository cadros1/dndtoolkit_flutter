# ADR-0001：本地 JSON 是角色数据的主要副本

## 背景

应用需要在 Windows 和 Android 离线创建、编辑和使用角色。云端只用于低成本备份，不应成为应用启动或跑团过程的依赖。项目已有使用 JSON 的真实用户数据。

## 决策

- 每个角色作为独立 `<UUID>.json` 保存在应用文档目录。
- `Character` 的 PascalCase JSON 是已发布兼容契约。
- 本地 JSON 是主要副本；PDF 是交换格式，Supabase 是手动备份副本。
- 数据结构修改必须向后兼容，迁移失败不得破坏原文件。
- 单个坏文件应提示并跳过，其他角色继续可用。

## 结果

优点：

- 离线简单可靠，角色天然分文件隔离。
- 易于调试、备份和跨端共享模型。
- 不需要数据库运行时或迁移工具才能启动。

代价：

- 跨角色查询和事务能力有限。
- 必须自行实现原子写入、schema version、迁移和坏文件恢复。
- 画像 Base64 会增大 JSON 文件。

## 被拒绝或暂缓的方案

- SQLite/Isar/Hive 等本地数据库：当前规模下增加迁移和平台复杂度，未来如角色量或查询需求显著增加再评估。
- 云端作为唯一主存储：违背离线优先和低成本目标。
