# ADR-0002：使用身份令牌和 Supabase RLS 提供云端备份

## 背景

云端需求只是区分不同用户的角色备份，不需要社交资料、密码、邮箱、组织或复杂权限。引入传统账户系统会增加用户摩擦、开发和运营成本。

## 决策

- 不使用 Supabase Auth 的 sign-up/sign-in。
- 客户端生成 UUID v4 身份令牌并保存在 `SharedPreferences`。
- 每个请求通过 `x-sync-token` 头发送令牌。
- `characters` 使用 `(id, sync_token)` 联合主键。
- Supabase RLS 对所有操作要求行的 `sync_token` 与请求头一致。
- 云端只保存角色 JSON，不保存画像。
- 备份由用户手动上传和下载；本地仍是主要副本。

## 结果

优点：

- 无注册、密码或邮件依赖。
- 跨设备只需复制令牌。
- RLS 在数据库层隔离数据，客户端查询保持简单。

代价与风险：

- 令牌既是身份又是密码，泄露即失去隔离。
- 无找回、吊销列表、设备管理或二次认证。
- `SharedPreferences` 不是强安全存储。
- 令牌更换不会迁移或删除旧数据。
- 数据不是端到端加密。

## 约束

- 不得在日志、测试、截图或错误中泄露令牌。
- 不得把该机制描述成传统账户或高安全认证。
- 未来多人联机不能未经重新设计就复用此令牌作为细粒度权限系统。
